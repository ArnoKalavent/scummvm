This project is an HD remaster toolkit for The Space Bar (1997), a game that runs on ScummVM's BAGEL engine. The target is the game at HD_SCALE (3: 1920×1440). Two kinds of change come through here: Python tools in spacebar_tools/ (with tests in tests/), and C++ engine changes for ScummVM's engines/bagel/ that live on the fork branch spacebar-hd and ship as one .patch file. Judge each by the rules for its kind. Anything that would make the game crash, load a corrupted asset, or silently produce wrong output for thousands of files is at least MAJOR.

## Both kinds

- HD_SCALE is the one knob. It is defined once in the engine and once in the tools, and every size, rect, constant and test derives from it. Flag as MAJOR any number used as the scale factor (a bare 2 or 3 where HD_SCALE is meant) or any pre-scaled size written as a literal (1280, 960, 1920, 1440, 6144 …) in code, tests or specs, and any new hardcoded 640/480/320/240/160 that isn't multiplied by HD_SCALE.
- Rects are inclusive: CBofRect width = right − left + 1, and WLD rects are read straight into it. A rect's far edge (right, bottom) scales as HD_SCALE·(r+1) − 1; a point (position, hotspot, BIN pair, cursor hotspot) scales as HD_SCALE·x. Flag k·r on a far edge and any off-by-one on the +1.

## Python tools

- Python 3.14. ruff must stay clean. Every behaviour change needs a test under tests/, and existing tests must not be weakened to pass. Tests that depend on the scale factor must run at more than one factor.
- WLD scaler: scaling then writing must reproduce non-coordinate content byte for byte, line endings and comments included. Scaling may touch only coordinates — rects `[x1,y1,x2,y2]`, positions `[x,y]`, hotspots `@[hotX,hotY]`, `DESC=…[…]` text rects (also on continuation lines that start with `VAR`), and `CURSOR n = x y` hotspots (cursor BMPs are upscaled, so their hotspots scale too). Signed values occur and must scale. Never touch TURNCOUNT values, VAR assignments, timer thresholds, PANIM frame indices, `%N` values or percentages. Flag any regex or tokenizer that could match a non-coordinate number or miss a coordinate.
- Idempotency: batch scalers (WLD, BIN, BMP, SMK→AVI) write into an override directory that mirrors the game tree. Running twice must not double-scale. Flag any runner that cannot tell scaled output from source, that reads from the directory it writes to (or one inside it), or whose resume treats a partial or wrong-scale output as done. Outputs must be written atomically.
- BIN files are int32 little-endian x,y pairs. Scaled values must stay in range, and rounding must match the WLD scaler's point rule exactly or sprites drift from their hotspots. Only the 197 coordinate BINs are scaled, never DIRECTX\DRIVERS\.
- BMP output must be 8-bit CLUT8 using the source file's exact palette (the game uses USESHAREDPAL — never re-derive a palette). Palette index 1 (RGB 255,7,162) is the global chroma key and must be excluded from dithering and quantization; the restored transparency mask must be the source mask scaled by nearest neighbour to the output size. 24-bit output, a re-derived palette or a mask at the wrong size is a BLOCKER.
- Video: SMK→AVI. The engine's decoder factory is extension-driven, so output must be `.avi`; non-INTRO videos must be pal8 with the source palette and the same chroma rules as BMPs; the BIN companion is scaled in the same pass by HD_SCALE. A failed audio extraction must fail the video, not produce a silent one.
- File handling at scale: ~5,900 assets. Flag loading whole trees into memory, and silent skips on error — a skipped asset is a missing texture in the game. Error messages must keep the line that says what failed. Watch Windows paths: backslashes, case-insensitive matching, the `$SBARDIR\` prefix, long paths.
- Never modify the game's original files. No tool may write into the game directory; `sbar-timer patch` and `restore` must refuse to run until the timer mod is redesigned. Any in-place write to source assets is a BLOCKER.
- Timer: any change that freezes TURNCOUNT or stops it incrementing, or that rewrites `TURNCOUNT + N` progression schedules, is a BLOCKER — it breaks bar progression. Only the game-over check (`TURNCOUNT >= 2250 …`, BAR.WLD:1055) and the engine hard cap may change.

## Engine patch (C++, ScummVM engines/bagel/)

- The fork branch spacebar-hd is the source of truth; the change ships as one patch, generated from the branch against upstream 7cf428776, that must `git apply --check` cleanly on a clean checkout of that commit. A change that wouldn't apply cleanly is MAJOR.
- Only engines/bagel/spacebar/ and the engines/bagel/ entry points already patched, plus three shared files: video/avi_decoder.cpp, video/avi_decoder.h and image/codecs/bmp_raw.cpp. Changes to those three must be behaviour-preserving for every other engine (gate new behaviour to BAGEL's case, e.g. PCM audio, negative-height BMPs); anything else there is MAJOR. engines/bagel/hodjnpodj/ is a different game on the same engine: any change there is a BLOCKER unless the task says otherwise.
- CBofBitmap is CLUT8-only. Any path that hands it 24-bit data, or a palette-less AVI, is a BLOCKER.
- Resolution constants derive from HD_SCALE: DEF_WIDTH/DEF_HEIGHT are inclusive maxima (640·HD_SCALE − 1 / 480·HD_SCALE − 1). The main window is DEF_WIDTH+1 × DEF_HEIGHT+1, not PAN_AREA_WIDTH × PAN_AREA_HEIGHT. Flag any off-by-one on the +1.
- Panoramic math is ratio-based through MAX_DIV_VIEW and needs no change for an integer HD_SCALE. Flag anything that hardcodes a viewport or panorama size instead (e.g. 2048, 1024), and panorama detection by width instead of _bPanorama.
- Warp correction: cosine correction is the default and the only mode at HD. The precomputed strip table (STRIP_POINTS, 480 columns) is 1×-only and must never run when the view is wider than the table; anything that reaches or depends on it at HD_SCALE > 1 is MAJOR.
- AVI fallback: every video-loading path goes through the AVI-before-SMK swap (spacebar.cpp, movie_object.cpp, character_object.cpp and any new site). A path that bypasses it is MAJOR. Unconverted SMKs must keep working, seeking included (Smacker needs forceSeekToFrame): breaking that is a BLOCKER.
- Override priority: extrapath at SearchMan priority 1, game data at 0. Anything that registers an archive at priority ≥1 or reorders initializePath silently breaks overrides.
- TURNCOUNT hard cap at var.cpp:305 (`== 2250` → skip increment). Raising it must be paired with the WLD threshold change; lowering it is a BLOCKER.
- Save games are resolution-specific; a change that claims to load saves across HD_SCALE values needs a test plan.
- Match the surrounding ScummVM code style.
- Rendering, panning, click alignment and audio cannot be verified from a diff. Label such findings UNVERIFIED and say exactly what to check on screen.
